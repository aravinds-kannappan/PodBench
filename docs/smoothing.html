Does a typo change the decision?

We gave Qwen2.5-0.5B-Instruct nine SQL work orders and two possible actions for each. We compared its answer on the original text with a vote across five copies, each containing a different typo. Each work order appeared with the actions in both possible positions.

The model chose the first option on all 18 clean presentations. Voting chose the first option every time as well. Reversing the actions turned a correct original choice into a miss on every work order. The apparent stability across typos therefore included nine stable wrong answers.

What the vote measures

We fixed the first three cases in each of three task families before inference. Each appeared with the authorized action first and second. We sampled five distinct positions in the work-order text. Each edit transposed two different adjacent letters inside a word, leaving the first and last letters, option text and numbers intact. Both option orders used the same five offsets. Every completion started a fresh chat.

We counted a vote for a single A or B, ignoring case, surrounding spaces and an optional final period or exclamation mark. At least three of the five completions had to select the same letter. Invalid completions supplied no vote. All 18 presentations contributed to accuracy, including any invalid clean choices or votes without a majority.

SmoothLLM combines character perturbations with a vote on whether responses meet a jailbreak criterion. Here the vote is on the action selected in a benign work order. This measures sensitivity to typing errors and option order on a small, fixed case set. The model made single-turn selections. Tool execution and learning over time require separate experiments. Repeat the comparison

It uses greedy decoding, a 12-token output limit and a fresh conversation per draw. The study seed is 20261124. Pinned model file · Study script
