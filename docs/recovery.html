Recovery experiment

Recovering after an ambiguous commit

The transaction timed out. The database may already have changed. Does asking an agent to inspect the state before retrying help it finish exactly once?

Inspection, submission and exact recovery

Across 192 episodes, neither model submitted an exact recovery. Asking for inspection increased first-action inspection in Qwen and decreased it in SmolLM2.

What the comparison measures

The recovery instruction changes in a fresh episode while the rest of the paired task stays fixed. A pass requires an explicit submission and the exact expected final database state. Each model has up to five decisions and can inspect under either instruction. The handoff text stays the same whether the preceding write committed or rolled back. The intervention asks for inspection, and the model chooses what to do next.

A scripted control that inspected the database and acted on the observation passed 24/24 fixture worlds. Blindly retrying passed 12/24, all in the previously uncommitted worlds. Assuming the first write had committed passed the other 12/24. These controls establish that each fixture is solvable within the five-decision budget. Reference policies

The study used four fixture seeds per task family and two quantized checkpoints running locally with greedy decoding. Reversed menu orders repeat the same underlying work order. The experiment measures recovery within one episode. It does not track learning or retention across jobs.
