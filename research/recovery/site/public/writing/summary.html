A recovery instruction changed the first action. Did it finish the job?

A worker loses its connection while recording a refund. The next worker knows which write was attempted, but the missing acknowledgement leaves open whether the money was already recorded. Repeating the write can duplicate a payment. Skipping it can leave a paid order marked refunded with an empty ledger. PodBench gives a model this handoff and lets it inspect and change a real, disposable SQLite database.

We compared a generic recovery instruction with the same instruction plus a request to inspect persisted state before writing. Across 192 scheduled episodes, the two locally runnable checkpoints produced 0 exact, submitted recoveries. Qwen inspected first in 0 of 48 generic episodes and 10 of 48 verify-first episodes. SmolLM2 inspected first in 16 of 48 and 12 of 48, respectively. Those changes in behavior did not establish which remaining writes the agent would execute or when it would declare the work finished.

The archive separates these outcomes. Models explicitly submitted 94 inexact databases. In 8 other episodes, the database met the verifier’s target and the agent never submitted. A handwritten controller solved each starting state by consulting the same inspection results available to the models. The protocols, action bindings, raw replies and replay code let another team check what the endpoint counted, or evaluate a different policy under the same constraints.

The frozen comparison concerns short, constructed handoffs under greedy decoding. A finite collection of uniformly unsuccessful episodes gives little information about effects on other models or workloads. Our subsequent analyses examine where the trajectories diverged, which alternatives a model scored, and whether changing what the model sees changes its next decision. These are exploratory tests selected after the endpoint was known. The trajectory search found that 90 episodes had lost every route to an exact submission at the opening decision. Immediate submission accounted for 80 of those cases. That distinction separates a worker that ended too soon from one that permanently overapplied a write. In an exploratory menu sweep Qwen recovered the committed refund on 2/24 presentations of the same work order. A practical next experiment would include a service-side request identifier alongside the instructional intervention, with new workflows and enough successful baseline episodes to make improvement measurable.
